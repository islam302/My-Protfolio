## Commands

```bash
# E2E (all 3 viewports; starts/reuses web, web-api and admin servers)
npm run test:e2e
npx playwright test --project=e2e-mobile            # one viewport
BASE_URL=https://staging.example.com npm run test:e2e   # deployed site (no local web server)

# Visual regression against the rebuilt apps/web (release gate)
npx playwright test tests/visual                     # or: PW_VISUAL=1 npx playwright test
PW_MAX_DIFF_RATIO=0 npx playwright test tests/visual # zero-tolerance run (used to measure exact diffs)

# Re-capture baselines FROM THE ORIGINAL build only (never from apps/web)
cd <original clone> && SITE_URL=https://islambadran.com PORT=4401 node scripts/serve.mjs
BASE_URL=http://localhost:4401 npx playwright test tests/visual --update-snapshots

npx playwright show-report                           # html report in playwright-report/
npx eslint tests playwright.config.js                # clean (exit 0)
```

`npm run test:e2e` = `playwright test`. The visual projects are left out unless the command line names `tests/visual` or a `visual-*` project, or `PW_VISUAL=1` is set. The decision is passed to the workers through `PW_VISUAL`.

**Determinism measures** (applied identically to both builds):
- `reducedMotion: 'reduce'`: home.js skips its entrance and the sway.
- `animations: 'disabled'` and `caret: 'hide'`.
- Every `[data-reveal]` gets `.is-in`.
- Lazy images are switched to eager and `img.decode()` is awaited.
- `document.fonts.ready` is awaited.
- `<video>` is paused and hidden via `stylePath` (it is transparent in the hero state anyway).
- Home waits until `.pre` count is 0.
- An instant `scrollTo(0)` before each full-page shot, because the site sets `scroll-behavior: smooth`.
- `deviceScaleFactor: 1`.
- Chromium flags `--disable-gpu --disable-lcd-text --font-render-hinting=none --force-color-profile=srgb --disable-partial-raster`.

No clock is needed: the footer and badge years are baked in at build time and are identical in both builds.

**Caveat: tablet visual project.** With `isMobile: true` + Desktop UA at 768 px, full-page captures of the case-study pages moved text by sub-pixel amounts from run to run. This happened even reference-vs-reference (0.01 ratio). The visual tablet project therefore runs with `isMobile: false`; the E2E tablet project keeps `isMobile: true`/`hasTouch`.

**Baselines are platform-specific.** They are stored under `__screenshots__/win32/`, captured on Windows. A Linux CI runner must capture its own `linux/` baselines from the original build with the command above. Do not copy the win32 ones.

## App bugs found

**QA-01 (low; pre-existing in the original, also in rebuild) — first click on Send is swallowed after an invalid blur.**
- Repro on `/contact/`:
  1. Fill the name and type.
  2. Type `Hi there` in the message and leave focus in the textarea.
  3. Click "Send on WhatsApp".
- Effect: mousedown blurs the textarea, the blur handler shows `#f-message-err`, the layout shifts, and the button moves (in the trace from y≈1799 to y≈880). The `mouseup`/`click` then land on the `<form>`, so no submit happens: no status text, focus not moved, a second click is needed.
- Event trace: `mousedown:BUTTON`, `mouseup:FORM`, `click:FORM`.
- Fix ideas: don't validate on blur when `relatedTarget` is a submit button, or reserve space for error text so it doesn't shift layout.
- Test: `contact.spec.js` "KNOWN BUG QA-01" (`test.fail`).

**QA-02 (low/medium in API mode) — whitespace-padded fields pass browser validation but fail the API schema.**
- `required`/`minlength` count raw characters; `inquiryCreateSchema` trims first.
- Repro in an API build: name `"   "`, message `"short" + 20 spaces`, submit.
- The browser accepts it and the WhatsApp hand-off opens. The POST body is `{"name":"","message":"short",…}`, which fails the schema (name min 1, message min 20). The server will return 400 and the brief is silently not stored.
- The same input also produces a WhatsApp text with `Name: ` empty, in the non-API mode and in the original.
- Fix: validate trimmed values in `contact.js` (e.g. `setCustomValidity` when `value.trim()` is empty or shorter than `minLength`).
- Test: `api-mode.spec.js` "KNOWN BUG QA-02" (`test.fail`).

**QA-03 (cosmetic/a11y nit; pre-existing)** — the mobile menu fades in with a 0.25 s `visibility` transition. Pressing Tab in the same frame as Enter on the toggle skips the (still hidden) links and goes to the breadcrumb. A human is unlikely to hit this; noted only. The test waits for the menu to be visible.

Verified OK, no bugs:
- No console errors or failed requests on any page.
- All images decode; og:image returns 200; JSON-LD is valid everywhere.
- Escape now returns focus to the toggle (the frontend's change is verified).
- API-mode fire-and-forget never blocks the hand-off.
- Admin escapes all API data, sends CSRF on every mutation, keeps the token only in memory, and handles 401/429/500.
